# 独自タイピングシステム 入力判定仕様

| 項目 | 内容 |
| --- | --- |
| 文書状態 | 誤入力・Backspace・基本ローマ字系列を決定済み |
| 最終更新 | 2026-08-02 |

## 1. 決定済みの基本動作

### 正入力

- 現在入力すべき位置に対して正しいキーが入力された場合、正タイプ数を1増やす。
- 正入力の場合だけ、次の入力位置へ進む。

### 誤入力

- 現在入力すべき位置と異なるキーが入力された場合、誤タイプ数を1増やす。
- 誤入力があっても入力位置を進めない。
- 次のキー入力も、誤入力前と同じ位置に対して判定する。
- 誤入力した文字を入力済み文字列へ確定済みとして追加しない。

### Backspace

- Backspaceによる入力内容の修正機能は設けない。
- 正タイプ数、誤タイプ数、入力位置をBackspaceで巻き戻さない。
- Backspaceの押下は入力判定上無視し、誤タイプ数へ含めない。
- ブラウザの履歴移動や画面遷移など、競技を妨げる既定動作は防止する。
- 必要であれば押下回数だけを異常確認用ログへ記録してよい。

### 競技終了後

- 制限時間終了後は入力判定を行わない。
- クライアント画面だけでなく、サーバー側でも終了時刻以後の入力結果を正式スコアへ含めない。

## 2. 許可するローマ字系列

同じ読みについて、最低限次の入力系列をすべて許可する。

| 読み | 許可する系列 |
| --- | --- |
| し | `si`, `shi` |
| ち | `ti`, `chi` |
| つ | `tu`, `tsu` |
| ふ | `hu`, `fu` |
| じ | `zi`, `ji` |
| しゃ | `sya`, `sha` |
| しゅ | `syu`, `shu` |
| しょ | `syo`, `sho` |
| ちゃ | `tya`, `cha`, `cya` |
| ちゅ | `tyu`, `chu`, `cyu` |
| ちょ | `tyo`, `cho`, `cyo` |
| じゃ | `zya`, `ja`, `jya` |
| じゅ | `zyu`, `ju`, `jyu` |
| じょ | `zyo`, `jo`, `jyo` |

### 「ん」

- `nn` は位置にかかわらず許可する。
- 子音の前と文末では単独の `n` も許可する。
- 母音、`n`、`y` の前では `nn` または `n'` を使用する。

### 促音と小さい仮名

- 促音「っ」は、次に入力する子音の重ね打ちを許可する。
- 促音単体の入力として `xtu` と `ltu` を許可する。
- 小さい仮名は `x` 始まりと `l` 始まりの両方を許可する。
- 長音符「ー」は半角ハイフン `-` で入力する。

### 共通処理

- アルファベットの大文字は小文字へ正規化して判定する。
- ブラウザの日本語IMEによる文字確定は使用せず、ローマ字キー入力を直接判定する。
- 参加実装間で結果が異ならないよう、主催者は共通の入力判定テストケースを配布する。

## 3. 判定例

入力対象が `typing` で、次の入力位置が `p` の場合を考える。

```text
入力対象: t y p i n g
入力済み: t y
次の位置:     p
```

ここで `x` を入力した場合は誤タイプ数だけを増やし、次の位置は `p` のままとする。その後 `p` を入力したときに正タイプ数を増やし、次の位置 `i` へ進む。

## 4. RFPからの変更

RFP 6.3には「誤入力を記録し、入力位置を戻さずに次の文字へ進める」とあるが、2026-08-02の仕様決定により、誤入力時は入力位置を進めない方式へ変更する。

コンペ参加開発者はRFP記載より、この入力判定仕様を優先する。

## 5. 実装者の裁量

次の項目は判定結果を変えない範囲で参加開発者が決められる。

- 誤入力時の色、揺れ、音などのフィードバック。
- カーソルや次の入力位置の表示方法。
- 入力済み部分のデザイン。
- Backspace押下時に案内を表示するか。
- キー入力イベントを処理する内部構成。

## 6. 未決事項

| ID | 未決事項 | 決定が必要な理由 |
| --- | --- | --- |
| I-004 | 句読点、英数字、記号、スペースの扱い | 問題データと入力判定へ影響する |
| I-005 | 長押しによるキーリピートを有効な複数入力として扱うか | 不正防止と入力結果へ影響する |
| I-006 | Shift、Control、Altなど判定対象外キーの扱い | 誤タイプ数を統一する必要がある |
