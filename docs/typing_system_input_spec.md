# 独自タイピングシステム 入力判定仕様

| 項目 | 内容 |
| --- | --- |
| 文書状態 | v1コア入力仕様決定済み |
| 最終更新 | 2026-08-02 |

## 1. 判定の正本

- 正誤判定、正タイプ数、誤タイプ数、入力位置、問題完了、競技終了判定はサーバー側を正本とする。
- クライアントは個々のキー入力をサーバーへ送信し、合計スコアや集計値だけを送信して正式結果とする方式は禁止する。
- クライアント表示とサーバー記録が異なる場合はサーバー記録を採用する。
- サーバーは自ら保持する問題セット、現在位置、許可入力系列、競技時間を使って判定する。

## 2. 正入力と誤入力

### 正入力

- 現在入力すべき位置に対して正しいキーが入力された場合、正タイプ数を1増やす。
- 正入力の場合だけ次の入力位置へ進む。
- 問題の最後の入力を完了した場合、Enterを要求せず自動的に次の問題へ進む。

### 誤入力

- 現在入力すべき位置と異なる判定対象キーが入力された場合、誤タイプ数を1増やす。
- 誤入力があっても入力位置を進めない。
- 次のキー入力も、誤入力前と同じ位置に対して判定する。
- 誤入力した文字を入力済み文字列へ確定済みとして追加しない。

### Backspace

- Backspaceによる入力内容の修正機能は設けない。
- 正タイプ数、誤タイプ数、入力位置をBackspaceで巻き戻さない。
- Backspace押下は入力判定上無視し、誤タイプ数へ含めない。
- ブラウザの履歴移動など、競技を妨げる既定動作は防止する。

## 3. 判定対象外入力

次は入力位置、正タイプ数、誤タイプ数を変更せず無視する。

- `event.repeat`が真であるキー長押しの反復イベント。
- Shift、Control、Alt、Metaなどの修飾キー単独押下。
- Control、Alt、Metaのいずれかを含むキー入力。
- 矢印、Tab、Escape、ファンクションキーなど、文字入力ではないキー。
- IMEの変換中・確定イベント。

判定対象外入力は誤タイプ数へ含めない。異常確認用として押下や発生回数をログへ記録してよい。

Shiftを必要とする文字は問題へ含めない。誤ってShiftと英字を同時に押した場合、英字は小文字へ正規化して判定する。

Spaceは問題へ含めない。Space押下は文字入力として扱い、現在位置の正解にならないため誤タイプ数を1増やす。

## 4. 禁止する入力

- コピー、貼り付け、ドラッグ・アンド・ドロップによる文字入力を無効にする。
- ブラウザの日本語IMEによる文字確定は使用できない。
- 入力欄以外から複数文字を一括挿入してはならない。
- 禁止操作による文字列を問題進行や正式スコアへ反映しない。

## 5. 許可するローマ字系列

同じ読みに対して、主催者の共通入力判定テストケースで許可された系列だけを有効とする。最低限、次を含む。

| 読み | 許可する系列 |
| --- | --- |
| し | `si`, `shi` |
| ち | `ti`, `chi` |
| つ | `tu`, `tsu` |
| ふ | `hu`, `fu` |
| じ | `zi`, `ji` |
| しゃ | `sya`, `sha` |
| しゅ | `syu`, `shu` |
| しょ | `syo`, `sho` |
| ちゃ | `tya`, `cha`, `cya` |
| ちゅ | `tyu`, `chu`, `cyu` |
| ちょ | `tyo`, `cho`, `cyo` |
| じゃ | `zya`, `ja`, `jya` |
| じゅ | `zyu`, `ju`, `jyu` |
| じょ | `zyo`, `jo`, `jyo` |

### 「ん」

- `nn`は位置にかかわらず許可する。
- 子音の前と文末では単独の`n`も許可する。
- 母音、`n`、`y`の前では`nn`または`n'`を使用する。

### 促音・小さい仮名・長音符

- 促音「っ」は、次に入力する子音の重ね打ちを許可する。
- 促音単体の入力として`xtu`と`ltu`を許可する。
- 小さい仮名は`x`始まりと`l`始まりの両方を許可する。
- 長音符「ー」は半角ハイフン`-`で入力する。

### 句読点

- 読点「、」は半角カンマ`,`で入力する。
- 句点「。」は半角ピリオド`.`で入力する。
- v1ではShiftを必要とする句読点・記号を問題へ含めない。
- スペースは表示文、読み、入力対象へ含めない。

## 6. 競技時間境界

- 正式な開始時刻と終了時刻はサーバー時刻で決定する。
- サーバー受信時刻が開始時刻より前の入力は無効とする。
- 入力受付期間を`開始時刻 <= サーバー受信時刻 < 終了時刻`とする。
- 終了時刻以後に受信した入力は判定せず、正式スコアへ含めない。
- クライアントに表示された時刻や、クライアントが申告した入力時刻を正式判定へ使用しない。

## 7. 共通テストケース

- 主催者は、許可・不許可の入力系列、正誤タイプ数、入力位置、問題遷移を含む共通テストケースをJSONで配布する。
- コンペ参加実装は共通テストケースすべてに合格しなければならない。
- 共通テストケースで許可されていない独自のローマ字系列を追加してはならない。
- テストケースの版を記録し、競技開始後に当該試合で使用する版を変更しない。

## 8. 判定例

入力対象が`typing`で、次の入力位置が`p`の場合、`x`を入力すると誤タイプ数だけを増やし、次の位置は`p`のままとする。その後`p`を入力したときに正タイプ数を増やし、次の位置`i`へ進む。

## 9. RFPからの変更

旧RFPに「誤入力後に次の文字へ進む」と記載されていた場合、この仕様を優先する。誤入力時は入力位置を進めない。

## 10. 実装者の裁量

- 誤入力時の色、揺れ、音などのフィードバック。
- カーソルや次の入力位置の表示方法。
- 入力済み部分のデザイン。
- Backspaceや禁止操作時に案内を表示するか。
- コア判定を変えないクライアント内部のイベント処理方法。
