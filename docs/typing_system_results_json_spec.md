# 独自タイピングシステム 確定結果JSON仕様

| 項目 | 内容 |
| --- | --- |
| 文書状態 | v1確定 |
| スキーマバージョン | `typing-results-v1` |
| 最終更新 | 2026-08-02 |
| 出力側 | 独自タイピングシステム |
| 取込側 | SportEase管理画面 |

## 1. 目的と運用

独自タイピングシステムは、3試合すべての結果を確定した後、クラス別の得点と順位だけをJSONファイルとして出力する。

運営者はSportEaseで取込先のタイピング用トーナメントを選択し、JSONをアップロードする。SportEaseは内容を検証して確認画面を表示し、運営者の確定操作後に6クラス分を一括登録する。

- 1ファイルを1トーナメントの最終結果とする。
- 必ず6クラス分を含める。
- 第1〜第3試合の正式結果がすべて揃うまで出力しない。
- 無効化した試行を得点へ含めず、再試合を確定した場合は新しい正式結果を使用する。
- 失格選手の当該試合得点は0として出力する。
- 個人名、選手ID、個人スコア、正・誤タイプ数、競技時間、問題、ログを含めない。
- 詳細な競技結果と順位計算根拠は独自タイピングシステムへ保存する。
- SportEaseはJSONの`rank`を正式順位として登録する。

## 2. JSON形式

```json
{
  "schema_version": "typing-results-v1",
  "export_id": "4ef87d60-2e74-477a-9c16-a93423d04c20",
  "classes": [
    {
      "class_name": "3-1",
      "match_1_score": 123,
      "match_2_score": 118,
      "match_3_score": 130,
      "total_score": 371,
      "rank": 1
    },
    {
      "class_name": "3-2",
      "match_1_score": 110,
      "match_2_score": 125,
      "match_3_score": 121,
      "total_score": 356,
      "rank": 2
    }
  ]
}
```

例では2クラスだけ記載しているが、実際の`classes`は必ず6要素とする。

## 3. 必須フィールド

### 3.1 ルートオブジェクト

| フィールド | 型 | 規則 |
| --- | --- | --- |
| `schema_version` | 文字列 | `typing-results-v1`固定 |
| `export_id` | UUID文字列 | 1つの確定結果版を識別するUUID v4 |
| `classes` | 配列 | クラス結果を必ず6件含める |

### 3.2 クラス結果

| フィールド | 型 | 規則 |
| --- | --- | --- |
| `class_name` | 文字列 | SportEaseに登録されたクラス名と完全一致 |
| `match_1_score` | 整数 | 第1試合のクラス選手スコア。0以上 |
| `match_2_score` | 整数 | 第2試合のクラス選手スコア。0以上 |
| `match_3_score` | 整数 | 第3試合のクラス選手スコア。0以上 |
| `total_score` | 整数 | 3試合の得点合計。0以上 |
| `rank` | 整数 | 独自タイピングシステムが確定した順位。1〜6 |

ルートオブジェクトとクラス結果へ、上記以外のフィールドを追加してはならない。

## 4. 得点と順位

```text
total_score = match_1_score + match_2_score + match_3_score
```

クラス順位は独自タイピングシステムで次の順に比較して決定する。

1. 3名分の整数総合スコア合計が高い。
2. 3名分の切り捨て前スコア合計が高い。
3. 3名分の正確率の算術平均が高い。
4. 3名分の誤タイプ数合計が少ない。
5. すべて同じ場合は同順位とする。

完全同点は同じ`rank`とし、次順位を飛ばす競技順位方式を使用する。

```text
1位、2位、2位、4位、5位、6位
```

SportEaseには同点比較の元データを渡さない。SportEaseは合計点の整合性を検証し、同じ合計点のクラス間についてはJSONの`rank`を信頼する。

## 5. ファイル形式

| 項目 | 仕様 |
| --- | --- |
| 拡張子 | `.json` |
| 文字コード | UTF-8、BOMなし |
| ルート | JSONオブジェクト |
| 最大サイズ | 16 KiB |
| ファイル名 | `typing-results.json`を推奨 |

- JSON標準に従い、コメント、末尾カンマ、`NaN`、`Infinity`を使用しない。
- 同じオブジェクト内でキーを重複させない。
- スコアと順位は小数・文字列・指数表記ではなくJSON整数で記述する。
- `class_name`はUnicode NFCへ正規化し、前後に空白を含めない。
- `classes`は`rank`昇順とし、同順位では`class_name`昇順とする。
- 同じ確定結果を再出力する場合は同じ`export_id`を使用し、結果を訂正した場合だけ新しい`export_id`を発行する。

機械検証用の正本は[typing-results-v1 JSON Schema](./typing-results-v1.schema.json)とする。実際に取り込める6クラス分の例は[完全サンプルJSON](./typing-results-v1.example.json)を参照する。JSON Schemaで表現できないクラス名の一意性、合計点、順位関係、重複取込はSportEaseの取込処理で検証する。

## 6. SportEase取込検証

SportEaseは、運営者が選択したタイピング用トーナメントに対して次を検証する。

- JSONとして読み取れ、許可されたフィールドだけで構成されている。
- `schema_version`が対応バージョンである。
- `export_id`が小文字のUUID v4である。
- `classes`が6件である。
- `class_name`が重複せず、取込先トーナメントの6クラスと完全に一致する。
- 4種類のスコアが0以上2,147,483,647以下の整数である。
- `total_score`が3試合の得点合計と一致する。
- `rank`が1〜6の整数である。
- 合計点が高いクラスの順位が、合計点が低いクラスより下になっていない。
- 同じ`rank`のクラスは同じ`total_score`である。
- 先頭の`rank`が1である。
- 配列内の1始まりの位置を`i`としたとき、各`rank`は直前と同じ値または`i`である。
- 直前のクラスと`total_score`が異なる場合、`rank`は`i`である。
- 配列が規定順に並んでいる。

同じ合計点に対する順位差は、独自タイピングシステム側の同点比較結果として受け入れる。

取込確認画面には6クラスについて、第1〜第3試合の得点、合計点、順位を表示する。エラーが1件でもある場合は正式反映できない。

## 7. 重複取込と訂正

- 6クラス分を1つのトランザクションで登録し、部分的に登録しない。
- SportEaseは`export_id`とアップロードファイルのSHA-256を記録する。
- 同じ`export_id`かつ同じ内容の再取込は、取込済みとして成功扱いにする。
- 同じ`export_id`で内容が異なる場合は拒否する。
- 取込先に別の`export_id`による結果がある場合、通常の追加登録は拒否する。
- 訂正時は独自タイピングシステムから新しい`export_id`で6クラス分を再出力する。
- SportEaseの運営者が置換操作を明示的に確認した場合だけ、旧結果を履歴へ残して6クラス分を一括置換する。

## 8. セキュリティ

- SportEaseは拡張子、ファイルサイズ、JSON構造、文字数、整数範囲をサーバー側で検証する。
- `class_name`を画面へ表示するときはHTMLエスケープする。
- JSONへ個人名、メールアドレス、認証情報、入力キー履歴を含めない。
- 取込、正式反映、置換について、操作日時、操作主体、`export_id`、SHA-256、成功・失敗を記録する。
