# 独自タイピングシステム 運営・試合状況機能仕様

| 項目 | 内容 |
| --- | --- |
| 文書状態 | コア要件確定・画面設計は実装者裁量 |
| 最終更新 | 2026-08-02 |

## 1. 目的

運営者がタイピングシステム単体で大会準備、3試合の進行監視、結果確認、一括確定、CSV出力までを行えることを目的とする。

## 2. 試合状況一括一覧

選択したトーナメントについて、第1〜第3試合と各試合6名の状態を一括確認できる画面または同等の運営機能を必須とする。

### トーナメント単位

- 大会名、トーナメント名、競技時間、問題セットとバージョン。
- 3試合それぞれの状態と確定状況。
- 確定済み人数と全18名中の進行状況。
- CSV出力の可否、最終出力日時、`export_id`。

### 試合単位

- 試合番号、試行ID、状態、開始・終了時刻。
- 接続人数、準備完了人数、競技中人数、終了人数。
- 未確定、確定、無効、再試合の状態。
- 実行可能な運営操作。

### 選手単位

- レーン番号、クラス・チーム、選手、出場順。
- 端末の未接続、接続、準備完了、切断、再接続。
- 競技中の進捗、正タイプ数、誤タイプ数。
- 終了後のWPM、正確率、総合スコア、結果状態。

競技中の状態は運営者の再読み込み操作なしで更新する。通信方式、更新間隔、表・カードなどの表現方法は参加開発者が選べる。

## 3. 必須運営操作

- 大会、トーナメント、チーム、選手、出場順、レーン、問題、競技時間の設定。
- 6台の選手端末の割り当て。
- 6名の準備状態確認と一括開始。
- 中断、強制終了、無効化、失格、再試合。
- 終了した1試合6名分の結果確認と一括確定。
- 確定した3試合分のCSV出力と再出力。

誤操作を防ぐため、開始、強制終了、無効化、失格、再試合、確定には確認操作を設ける。無効化、失格、再試合には理由を記録する。

## 4. 状態の最低要件

```text
未開始 → 準備中 → 競技中 → 終了・未確定 → 確定
                         └→ 無効 → 再試合の準備中
確定 → 無効または失格
再試合確定 → 以前の試行を差し替え済み
```

- 6名全員が割り当て済みでなければ準備中へ進めない。
- 6名全員が準備完了でなければ正式試合を開始できない。
- 競技中の出場者、レーン、競技時間、問題セットを変更できない。
- 競技終了直後の結果は未確定とし、自動確定しない。
- 6名分が揃わなければ確定できない。
- 確定済み結果は直接編集しない。

## 5. 権限と記録

- 運営者だけが試合開始、停止、結果確定、無効化、失格、再試合、CSV出力を実行できる。
- 選手は割り当てられた試合の入力操作だけを行える。
- 観客は閲覧だけ可能とする。
- 必須運営操作について、日時、操作主体、対象、変更前後、理由を記録する。

## 6. 実装者の裁量

- 画面数、画面遷移、表・カード・ダッシュボードなどのレイアウト。
- 配色、アニメーション、効果音、観戦演出。
- QRコード、参加コード、専用URLなどの端末割り当て方法。
- WebSocket、Server-Sent Events、ポーリングなどの状態配信方式。
- 必須項目に加えて表示する統計や分析。
