| 項目 | 内容 |

## 1. 変数

| 記号 | CSV列・内部フィールド | 定義 |
| --- | --- | --- |
| `C` | `correct_types` | 競技時間内の正タイプ数。0以上の整数 |
| `M` | `incorrect_types` | 競技時間内の誤タイプ数。0以上の整数 |
| `T` | `duration_seconds` | スコア計算に使用する競技時間（秒） |

## 2. 計算式（決定済み）

```text
WPM = C ÷ T × 60

正確率 = C ÷ (C + M)

総合スコア = floor(WPM × 正確率³)
```

正確率は0〜1の比率として計算する。95%の場合、総合スコアの計算には `0.95` を使用し、`95` は使用しない。

`C + M = 0` の場合は、0除算を避けるため次の値とする。

```text
WPM = 0
正確率 = 0
総合スコア = 0
```

この仕様でいうWPMは、一般的な「5文字を1単語として換算するWPM」ではなく、主催者が定義した「1分あたりの正タイプ数」を表す。実装者が独自に5で割ってはならない。

## 3. 決定的な計算

浮動小数点の途中丸めによる実装差を避けるため、総合スコアはWPMや正確率の表示値から計算せず、元データから直接計算する。

上の式は次の式と同値である。

```text
総合スコア = floor(60 × C⁴ ÷ (T × (C + M)³))
```

- `floor` は小数点以下を切り捨てる。
- WPMと正確率の表示を丸めても、総合スコアの計算には丸めた値を使わない。
- 整数演算の場合は、`C⁴` などの中間値がオーバーフローしない型を使用する。
- 同じ `C`、`M`、`T`、`formula_version` からは必ず同じ総合スコアを得る。

## 4. 計算例

```text
C = 421
M = 18
T = 180

WPM = 421 ÷ 180 × 60
    = 140.333...

正確率 = 421 ÷ 439
       = 0.958997...

総合スコア = floor(140.333... × 0.958997...³)
             = 123
```


## 5. チームスコア

SportEaseは各チーム3名の個人総合スコアを合計してチームスコアとする。

```text
チームスコア = 第1試合の選手スコア
             + 第2試合の選手スコア
             + 第3試合の選手スコア
```

3試合分が揃うまではチーム最終スコアを確定しない。

## 6. 競技時間と途中終了

- 有効な正式試合では、設定された競技時間を全6名共通の `T` として使用する。
- 選手端末が切断・離脱してもサーバー時計は止めない。
- 選手端末ごとに異なる競技時間を使用しない。
- 設定時間より前に終了した試合は、有効な正式試合として認めない。
- 障害や運営判断で安全のため停止することはできるが、その試合は無効化し、スコアを確定せず再試合する。
- 途中終了時の実経過時間を使ってWPMや正式スコアを計算しない。

例えば競技時間が180秒の場合、有効な正式結果の `duration_seconds` は全員 `180` となる。

## 7. 同点処理

### 個人順位

整数の総合スコアが同じ場合、次の順で比較する。

1. `floor` 前の `raw_score = WPM × 正確率³` が高い。
2. 正確率が高い。
3. WPMが高い。
4. 誤タイプ数が少ない。
5. すべて同じ場合は同順位とする。

表示用に丸めたWPM・正確率ではなく、元データから計算した値を比較する。クラス名、選手名、登録順など競技成績と無関係な値で順位を決めない。

### チーム順位

整数のチームスコアが同じ場合、次の順で比較する。

1. 3名分の `raw_score` 合計が高い。
2. 3名分の正確率の算術平均が高い。
3. 3名分の誤タイプ数合計が少ない。
4. すべて同じ場合は同順位とする。
