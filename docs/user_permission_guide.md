## 1. 権限レベルの概要

SportEaseでは、`root`、`admin`、`student` の3つの基本権限を利用します。クラス単位の操作対象は、プロフィールで設定された `class_id` から決定します。

| 権限レベル | 説明 | 対象ユーザー |
|-----------|------|-------------|
| **Root** | システム管理者。全ての機能にアクセス可能 | システム運営者 |
| **Admin** | イベント運営者。Admin機能とStudent機能にアクセス可能 | 教員・スタッフ |
| **Student** | 一般ユーザー。学生向け機能にアクセス可能 | 生徒 |

### 権限の取得方法
- **Root/Admin/Student**: Rootユーザーが「権限管理」画面から `admin` / `root` を付与・剥奪します。`student` は基本ロールとして付与されます。
- **クラス所属**: 初回ログイン時に選択したクラスをプロフィールへ保存します。プロフィール完了後は一般ユーザーによる変更はできません。
- **春秋の引き継ぎ**: 同年度の秋大会を作成すると、春大会の在籍人数を同名クラスへ引き継ぎます。秋大会に登録済みの人数は上書きしません。`専教`は在籍人数を設定しないため、引き継ぎ対象外です。また、同年度の大会を「準備中」または「開催中」にすると、同名クラスへ所属を引き継ぎ、表示名とプロフィール完了状態を維持します。春大会を終了して有効大会がない期間を挟んでも引き継ぎます。競技のチーム編成は大会ごとに登録します。
- **競技ロール**: `IS4_バスケットボール` などの競技ロールは大会ごとに付与・解除します。ユーザー情報、ロール管理画面、通知の宛先には現在の大会の割り当てだけを反映し、春の参加者を秋の通知対象に含めません。同じ競技に春秋とも参加する場合も、それぞれの割り当てを保持します。`root` / `admin` / `student` と大会共通の任意ロールは引き継ぎます。

## 2. Root専用機能

Root権限を持つユーザーのみがアクセスできる機能です。

### 2.1 大会情報登録・管理
**パス**: `/dashboard/root/event-management`

**機能概要**: スポーツ大会（イベント）の作成・編集を行います。

**使用方法**:
1. サイドバーの「Root」セクションから「大会情報登録・管理」をクリック
2. 「新規大会作成」ボタンから新しい大会を登録
3. 既存の大会名をクリックして設定を編集

**設定項目**:
- 大会名
- 年度・シーズン（春／秋）
- 開始日・終了日
- アンケートURL
- 大会のステータス（準備中/予定/開催中/アーカイブ）
- 2競技への重複登録を許可するクラス人数（初期値：31）
- 学生画面でのスコア表示／非表示

**出力・連携機能**:
- 登録したアンケートURLの全体通知
- 秋季大会のアンケート得点CSVインポート（1回答1行形式／`クラス名,人数` の集計形式）。得点率の分母には、同年度の春大会から引き継いだ在籍人数を使用します。春大会で未設定の場合は「各クラス人数設定」で登録します。`専教`はアンケート得点の対象外です
- クラス別結果のCSV・PDF出力
- データベースのSQLダンプ出力
- アップロード済み画像・PDFのZIP出力

**重複登録のルール**:
- 原則として、選手は同一大会で1競技まで登録できます。
- 設定した人数以下のクラスは、選手1人につき2競技まで登録できます。
- 専攻科・教員チーム（`専教`）は重複登録の上限対象外です。
- この設定は大会ごとに保存されます。クラス人数設定で登録した在籍人数に合わせて設定してください。

**大会ステータスの運用**:

| ステータス | 利用目的 |
| --- | --- |
| 準備中 | 競技登録、チーム編成、トーナメント生成、昼競技設定などを行う状態です。現在操作する大会として選択されます。 |
| 予定 | 開催前の大会情報を保管する状態です。 |
| 開催中 | 大会当日の運用状態です。試合結果と昼競技結果を入力できます。 |
| アーカイブ | 終了した大会の参照用状態です。 |

**パス**: `/dashboard/root/rainy-mode`

**機能概要**: 雨天時の代替競技スケジュールへの切り替えを管理します。

**使用方法**:
1. サイドバーから「雨天時モード管理」をクリック
2. 雨天モードのON/OFFを切り替え
3. 雨天時の競技スケジュールを確認・調整

---

### 2.3 競技情報登録・管理
**パス**: `/dashboard/root/sport-management`

**機能概要**: 大会で実施する競技の登録・編集・削除を行います。

**使用方法**:
1. サイドバーから「競技情報登録・管理」をクリック
2. 「新規競技追加」から競技を登録
3. 競技名、ルール、開催日時、場所などを設定

**設定項目**:
- 競技名
- 競技種別（個人/団体）
- 参加対象学年
- 開催日時・場所
- ポイント配分

---

### 2.4 通知管理
**パス**: `/dashboard/root/notification`

**機能概要**: 全ユーザーへのプッシュ通知を管理・送信します。

**使用方法**:
1. サイドバーから「通知管理」をクリック
2. 「新規通知作成」でタイトルと本文を入力
3. 宛先の指定方法（ロール単位 / 個人単位）を選び、対象ロールまたは検索したユーザーと通知タイプを選択
4. Push通知を受信できる対象人数を確認し、「送信」ボタンで即時配信

Push通知を有効にしていない利用者にも、対象者のアプリ内通知一覧には通知が表示されます。予約送信、学年・クラス単位の宛先指定はこの画面では提供していません。

---

### 2.5 通知申請管理
**パス**: `/dashboard/root/notification-requests`

**機能概要**: 学生からの通知申請を承認・却下します。

**使用方法**:
1. サイドバーから「通知申請管理」をクリック
2. 申請一覧から内容を確認
3. 「承認」または「却下」を選択
4. 承認された通知は自動的に全体へ送信

---

### 2.6 トーナメント生成・管理
**パス**: `/dashboard/root/tournament-management`

**機能概要**: 通常競技と盤上競技のトーナメント表を生成・管理します。

**使用方法**:
1. サイドバーから「トーナメント生成・管理」をクリック
2. 通常競技は対象競技を選び、個別生成または一括生成のプレビューを確認して確定
3. 盤上競技は「将棋（A・B個人戦）」または「オセロ（クラス対抗）」を選択
4. シード順をドラッグ＆ドロップで並べ替え、名称・日時・会場・得点・試合時間・PDFを確認
5. 「生成」または「再生成」で公開
6. 保存済みトーナメントがある場合は「保存済みトーナメントをExcel出力」から全ブラケットをダウンロード

**盤上競技の扱い**:
- 将棋・オセロは通常競技の一括生成対象外で、専用フォームからのみ生成します。
- 参加クラスは `1-1`、`1-2`、`1-3`、`IE2`〜`IE5`、`IS2`〜`IS5`、`IT2`〜`IT5`、`専教` の16クラス固定です。画面では参加クラス選択を行いません。
- 将棋はA・Bの2ブラケット、オセロは1ブラケットを生成します。各ブラケットのシード順を個別に設定できます。
- 将棋の代表A・代表B・補欠、オセロの代表者はAdminの「クラス・チーム割り当て」で事前に登録します。

### 2.7 昼競技管理
**パス**: `/dashboard/root/noon-game`

**機能概要**: 昼休みに行われる特別競技を、複数セッション単位で設定・管理します。

**使用方法**:
1. サイドバーから「昼競技管理」をクリック
2. 学年対抗リレー、コース対抗リレー、綱引き、競技タイピング、借り物競争のテンプレートから競技を作成
3. セッション名、実施日時、場所、編成、試合、順位点を設定
4. 競技タイピングは `typing-results-v1` 形式のJSONを取り込み、必要な場合だけ置換インポートを実行

### 2.8 権限管理
**パス**: `/dashboard/root/user-promotion`

**機能概要**: ユーザーに `admin` / `root` の基本権限を付与・剥奪します。

**使用方法**:
1. サイドバーから「権限管理」をクリック
2. メールアドレスまたは表示名でユーザーを検索
3. 対象ユーザーの `admin` または `root` 列から「付与」または「剥奪」を実行

**注意**:
- この画面で変更できるのは `admin` / `root` の基本権限のみです
- 任意ロールの付与・削除は Admin の「ロール管理」から行います

### 2.9 各クラス人数設定
**パス**: `/dashboard/root/class-student-count`

**機能概要**: 各クラスの生徒数を設定します。チーム編成の基準になります。

**使用方法**:
1. サイドバーから「各クラス人数設定」をクリック
2. 学年・クラスごとに人数を入力
3. 「保存」で設定を反映

**注意**: `専教`は在籍人数による判定の対象外であり、手動設定一覧とCSV更新のどちらにも含めません。

---

### 2.10 ユーザー管理
**パス**: `/dashboard/root/change-username`

**機能概要**: ユーザーの検索・絞り込み、表示名変更、マスターロール切り替え、任意ロールの追加・削除を行います。

**使用方法**:
1. サイドバーから「ユーザー管理」をクリック
2. 名前・メールアドレスで検索し、必要に応じてクラス・ロールで絞り込み、並び順を指定
3. 「管理」を開き、表示名、`student` / `admin` / `root` のマスターロール、その他の任意ロールを更新

**注意**: クラス所属はこの画面では変更しません。廃止済みのクラス代表ロールも追加できません。競技参加ロールを操作する場合は現在の大会が正しいことを確認します。

### 2.12 競技要項アップロード

## 3. Admin機能（Admin/Root共通）

Admin権限以上のユーザーがアクセスできる機能です。

### 3.1 クラス・チーム割り当て
**パス**: `/dashboard/admin/class-management`

**機能概要**: 生徒を各競技のチームに割り当てます。

**使用方法**:
1. サイドバーの「Admin」セクションから「クラス・チーム割り当て」をクリック
2. 競技を選択
3. クラスと参加者を選択してチームに割り当て
4. 「保存」で確定

**備考**: この画面はAdmin/Root専用です。任意のクラスを対象に操作できます。重複登録の上限を超える選手が含まれる場合は登録できません。上限は大会情報登録・管理でrootが設定します。盤上競技では、将棋の代表A・代表B・補欠とオセロの代表者を登録します。

---

### 3.2 ロール割り当て・管理
**パス**: `/dashboard/admin/role-management`

**機能概要**: 審判ロールなど、イベント運営で必要になる任意ロールの付与・削除を行います。

**使用方法**:
1. サイドバーから「ロール割り当て・管理」をクリック
2. ユーザーを検索
3. 任意のロールを付与または削除

**注意**:
- `root` / `admin` / `student` の基本権限はこの画面では変更できません
- クラス単位の操作対象はロールではなくプロフィールのクラス所属で決まります
- 競技参加用ロールは大会単位で保持され、別大会の通知対象や割り当てへ混在しません

---

### 3.3 バーコード読み取り
**パス**: `/dashboard/admin/barcode-reader`

**機能概要**: 学生証等のMyIDバーコードを読み取り、参加本登録とラウンドチェックインを行います。

**使用方法**:
1. サイドバーから「バーコード読み取り」をクリック
2. 競技と試合を選択
3. カメラでMyIDバーコードを読み取る、またはバーコード値を手入力
4. 読み取り成功で参加本登録とラウンドチェックインを完了

---

### 3.4 参加本登録確認

---

### 3.5 試合結果入力

## 4. Student機能（全ユーザー共通）

Student権限以上の全ユーザーがアクセスできる機能です。

### 4.1 マイページ
**パス**: `/dashboard/student/my-page`

**機能概要**: 自分のプロフィール、クラス成績、参加試合、直近の試合結果、クラス状況、大会資料を一画面で確認します。

**使用方法**:
1. サイドバーの「Student」セクションから「マイページ」をクリック
2. 「参加試合」で割り当て競技と今後の通常競技・昼競技の日時、対戦相手、場所を確認
3. 「試合結果」で自分が所属するチームの直近5試合の勝敗、スコア、ラウンドを確認
4. 「クラス状況」で出席人数、参加競技数、競技ごとの進捗を確認
5. 「最新のお知らせ」で直近3件の通知を確認
6. 「大会資料・リンク」から大会要項PDF、競技要項PDF、公開中のアンケートを開く

**表示条件**:
- 得点公開中は、クラスの順位・得点・内訳も表示します。
- 一般学生への得点公開が停止されていても、参加試合、試合結果、クラス状況、お知らせ、大会資料は表示します。admin・rootは得点公開設定にかかわらず得点を確認できます。
- アンケートリンクは、rootがアンケートを公開済みにした場合のみ表示します。
- 大会要項または競技要項PDFが登録されていない場合、該当リンクは表示しません。

**備考**: 初回ログイン時に選択したクラスがプロフィールに保存され、参加試合・試合結果・クラス状況の対象を決定します。プロフィールの表示名はダッシュボード上部のユーザーメニューから変更します。

---

### 4.4 トーナメント

### 4.5 結果一覧
**パス**: `/dashboard/student/results`

**機能概要**: 開催中大会の確定済み結果を競技横断で確認します。

**表示内容**:
- 通常競技は完了した試合について、競技名、ラウンド、対戦チーム、スコア、勝者を表示します。
- 昼競技は公開済みの各セッションについて、順位・獲得点または勝者を表示します。
- 入力途中または未公開の結果は表示しません。

---

### 4.6 MyIDバーコード提示
**パス**: 学生側の発行画面はありません

**機能概要**: 大会当日に学生証等のMyIDバーコードを運営スタッフへ提示し、参加本登録を受けます。

**使用方法**:
1. 受付または競技開始前の案内に従う
2. 運営スタッフへMyIDバーコードを提示
3. 読み取れない場合は学籍番号を伝え、運営スタッフに手入力してもらう

## 5. 共通機能

### 5.1 ダッシュボードのショートカット

ログイン後のダッシュボードには、現在の権限で利用できる画面へのショートカットが表示されます。「表示設定」から不要な項目を非表示にできます。設定はブラウザのローカルストレージへ保存されるため、別端末や別ブラウザには引き継がれません。サイドバーのメニューは非表示になりません。

### 5.2 資料
**パス**: `/dashboard/guide`

**機能概要**: アプリケーションの使い方ガイドや各種資料を閲覧します。

**使用方法**:
1. サイドバー下部の「資料」をクリック
2. 目的のガイドを選択して閲覧

### 5.3 報告・提案リンク

ダッシュボードのヘッダーから、GitHubの専用フォームを開けます。

- バグ報告: 公開Issueとして不具合を報告
- 脆弱性報告: Security Advisoryから非公開で報告
- 新機能提案: 公開Issueとして改善案を提案

個人情報、認証情報、未修正の脆弱性は公開Issueへ書かず、脆弱性報告を使用してください。

### 5.4 過去大会アーカイブ
**パス**: `/dashboard/archive`

終了済み大会のクラス順位、通常競技トーナメント、昼競技結果を参照します。アーカイブは閲覧専用です。

### 5.5 プライバシーポリシー
**パス**: `/dashboard/privacy-policy`

取得する利用者情報、利用目的、保存・取扱方針を確認します。

## 補足情報

### プッシュ通知について
- Student、Admin、Root権限を持つユーザーがプッシュ通知を受信できます
- ブラウザの通知許可が必要です
- 同一ユーザーは最大5台の端末・ブラウザを登録できます。不要になった端末では通知設定から解除してください
- Push通知を受け取れない場合でも、アプリ内の通知一覧から内容を確認できます

### セキュリティについて
- 各機能は権限に応じてフロントエンド（画面表示）とバックエンド（API）の両方で保護されています
- 権限のない機能にアクセスしようとすると、ダッシュボードにリダイレクトされます

### 権限の階層
```
Root > Admin > Student
```
上位の権限は下位の権限の機能全てにアクセスできます。
